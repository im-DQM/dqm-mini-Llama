# Qwen2-0.5B-Instruct-Q8_0 性能报告（2026-10-28 · 最终版）

> 对象：dqm-mini-llama，完整模型 `Qwen2-0.5B-Instruct-Q8_0.gguf`。
> 范围：CPU 四档 matmul 模式 + 本机 CUDA（RTX 4060 Laptop）+ 远程 CUDA（RTX 4090D）。
> 说明：本文的**最终测试结果以这一轮为准**，早期轮次的数字（见 `2026-10-27-cpu-avx2-q8_0.md` 与工作区笔记）
> 受热降频、后台负载影响，只作趋势参考，不用于对外比较。

---

## 0. 结论速览

| 场景 | tokens/s | 相对 naive |
|---|---|---|
| CPU · naive（单线程标量） | 2.58 | 1.00× |
| CPU · SIMD（单线程 AVX2） | 5.97 | 2.31× |
| CPU · threaded（20 线程标量） | 6.25 | 2.42× |
| CPU · threaded-SIMD（20 线程 AVX2） | **6.98** | **2.71×** |
| CUDA · 本机 RTX 4060 Laptop | 38.01 | 5.4×（对最快 CPU） |
| CUDA · 远程 RTX 4090D | **60.95** | **8.7×**（对最快 CPU） |

一句话：在 i7-13650HX 上，SIMD 与多线程各自只带来约 2.3–2.4 倍，叠加 2.7 倍，因为 decode 卡在内存带宽，
不是算力；换到 GPU 才是量级变化——4090D 是最快 CPU 配置的 8.7 倍。

## 1. 测试环境

| 项目 | 值 |
|---|---|
| CPU | Intel Core i7-13650HX，14 核 20 线程（6 P 核 + 8 E 核） |
| 内存带宽 | 笔记本 DDR5 双通道（decode 的主要瓶颈） |
| 本机 GPU | NVIDIA GeForce RTX 4060 Laptop |
| 远程 GPU | NVIDIA GeForce RTX 4090D |
| 运行环境 | WSL2（Linux x86_64） |
| 编译 | Release `-O2`，`-mavx2 -mfma`，GCC |
| 模型 | `models/chat/Qwen2-0.5B-Instruct-Q8_0.gguf`（507 MB；vocab 151936，dim 896，24 层，heads 14/2，head_dim 64） |
| 采样 | greedy（`--temperature 0 --seed 1`），输出可复现 |
| 线程 | 20（`hardware_concurrency`） |

注：WSL 内 `/proc/cpuinfo` 的 `cpu MHz` 恒为固定值，读不到真实频率；笔记本长时间满载会热降频，
所以跨分钟的数字不可直接比较，本报告只用**同一轮**内的横向对比。

## 2. 测量方法

- 一次完整会话共 **4 轮**：第 1 轮是一条长 prompt（transformer / attention / RoPE / 量化推理那段英文材料），
  第 2–4 轮是在同一会话里追问（两句总结、三个关键事实、一段主旨），上下文累积。
- 累计 **prompt 863 tokens**、**实际生成 198 tokens**；**统计不含模型加载时间**。
- 正式测试前先跑 3 轮闲聊预热，避免首轮冷启动把数字拉低。
- 会话结束前用 `/stats` 取全会话统计，与逐轮 decode 数字互相对照。
- 四种模式各跑一遍完整会话：`naive`（单线程标量）、`simd`（单线程 AVX2）、
  `threaded`（20 线程标量）、`threaded-simd`（20 线程 AVX2，默认）。
- 三种硬件（CPU / 4060 / 4090D）用**同一套 prompt 与会话脚本**，只换后端。

## 3. CPU 结果

| 模式 | tokens/s | 相对 naive | 相对上一档 |
|---|---|---|---|
| naive | 2.58 | 1.00× | — |
| simd | 5.97 | 2.31× | 2.31× |
| threaded（20） | 6.25 | 2.42× | 1.05×（对 simd） |
| threaded-simd（20） | 6.98 | 2.71× | 1.12×（对 threaded） |

读法：

- SIMD 是这一轮里最划算的一步，单线程就有 2.31 倍；
- 再上 20 线程只多 1.05 倍，两个手段叠加 2.71 倍，远小于「2.31 × 2.42 ≈ 5.6」的理想乘积。

## 4. CUDA 结果

| 后端 | tokens/s | 相对最快 CPU（6.98） | 相对 4060 |
|---|---|---|---|
| RTX 4060 Laptop | 38.01 | 5.4× | 1.00× |
| RTX 4090D（远程） | 60.95 | **8.7×** | 1.60× |

- GPU 上的瓶颈从内存带宽换成 kernel 效率：0.5B 模型在 4090D 上跑不满算力，主要时间花在小 batch 的 kernel 启动与同步上。
- 4090D 相对 4060 只有 1.6 倍，而两者硬件规格差距远大于此——说明当前 CUDA 路径还没有针对小模型做批量化与融合。

---

## 5. 为什么 SIMD 和多线程不成倍

一句话：**decode 的瓶颈是内存带宽，不是算力**。SIMD 和线程都在加速"算"，但数据搬不过来，算得再快也得等。

### 5.1 算术强度太低（roofline）

Q8_0 权重 507 MB，每生成一个 token 要完整读一遍，做约 1 GFLOP 的乘加，
即每读 1 字节只做约 2 次浮点运算；CPU 的机器平衡点通常在 10–50 FLOP/byte，实测低了一到两个数量级，属于纯访存瓶颈。

- 加 SIMD：一条指令算 8（甚至 32 个 int8），省的是计算时间，不是搬运时间；
- 加线程：所有线程共享同一条内存带宽，带宽打满后多开线程只是排队。

### 5.2 收益不能相乘

若 SIMD（2.31×）与多线程（2.42×）互相独立，叠加应是约 5.6 倍；实测 2.71 倍，
差额全部被带宽吃掉——它们抢的是同一个瓶颈。

### 5.3 线程还有额外成本

- 每 token 的每个 Linear 都要做一次 `ParallelFor` 同步（唤醒 worker、mutex、条件变量），层数一多就是上百次；
- 20 线程时每个线程分到的行数变少，计算/同步比恶化；
- 超过拐点后是过订阅：早期 4 线程 / 20 线程的对照里，F32 路径 20 线程反而慢 10–12%。

### 5.4 Amdahl 定律

只有 Linear 被并行化。RmsNorm、Softmax、RoPE、采样、tokenizer 仍是串行，
每 token 的固定开销不随线程数下降，所以线程数的边际收益很快见顶。

## 6. 下一步该做什么（按性价比排序）

1. **批量 prefill（GEMM）**：当前 `ForwardBatch` 是逐 token 调 `ForwardToken`，权重每个 token 重读一遍，
   批量后同一份权重可复用多次，算术强度成倍提升——这是唯一能同时吃到 SIMD 与线程收益的改动。
2. **CUDA 侧做融合与批处理**：4090D 只比 4060 快 1.6 倍，说明 kernel 启动与同步占了主导，
   把 RMSNorm、RoPE、采样等小算子融合掉，再上批量，才有机会接近硬件上限。
3. **Q8 AVX2 内核继续打磨**：反量化放进寄存器、一次处理一批 int8，减少逐元素函数调用开销。
4. **tokenize 单独排查**：每轮 `tokenize_ms` 稳定在 0.75–1.04 s，相对整体偏慢。

## 7. 复现

```bash
# CPU 四档
./build/dqm_llama -m models/chat/Qwen2-0.5B-Instruct-Q8_0.gguf -t 20 --matmul threaded-simd
# CUDA
./build/dqm_llama -m models/chat/Qwen2-0.5B-Instruct-Q8_0.gguf --backend cuda
```

会话内先跑 3 轮预热，再依次输入长文与三条追问；结束前 `/stats` 取统计。
